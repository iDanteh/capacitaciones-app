Modelo multi-tenant y sub-empresas

Aislamiento de datos por empresa y jerarquía de tenants

Cada empresa (Tenant) tiene sus propios usuarios, cursos y datos. Los tenants Business/Enterprise pueden crear sub-empresas (tenants hijo). El OWNER padre puede acceder a sus sub-empresas sin login separado vía POST /auth/switch-tenant — se crea un usuario espejo automáticamente.

04

Flujo de autenticación

Login normal, 2FA/MFA TOTP, tokens JWT y cambio de contexto de tenant

Los access tokens expiran en 15 minutos. Los refresh tokens duran 7 días y se rotan en cada uso (solo el hash SHA-256 se persiste en base de datos). El 2FA usa TOTP (RFC 6238) — secret cifrado AES-256-GCM en la BD.

sequenceDiagram actor U as Usuario participant F as Frontend participant A as API /auth participant DB as PostgreSQL rect rgb(239, 246, 255) Note over U,DB: Flujo 1 — Login estándar U->>F: Ingresa email + contraseña + slug F->>A: POST /auth/login A->>DB: Buscar tenant por slug A->>DB: Buscar user por tenantId+email A->>A: bcrypt.compare(pwd, hash) A->>DB: INSERT refresh_token (solo hash SHA-256) A-->>F: { accessToken, refreshToken, user } F->>F: localStorage.setItem(access_token, refresh_token, user) end rect rgb(240, 253, 244) Note over U,DB: Flujo 2 — Login con 2FA activo U->>F: Ingresa email + contraseña + slug F->>A: POST /auth/login A->>DB: mfaEnabled = true A-->>F: { mfaPending: true, mfaToken (JWT 5min) } F->>F: Muestra input OTP de 6 dígitos U->>F: Ingresa código TOTP (Google Authenticator) F->>A: POST /auth/mfa/verify { mfaToken, code } A->>A: Valida TOTP o backup code A->>DB: INSERT refresh_token A-->>F: { accessToken, refreshToken, user } end rect rgb(255, 247, 237) Note over U,DB: Flujo 3 — Renovación silenciosa de tokens F->>A: Cualquier request con token expirado A-->>F: 401 Unauthorized F->>A: POST /auth/refresh { refreshToken } A->>DB: Buscar hash(refreshToken), verificar no revocado A->>DB: UPDATE refreshToken revokedAt=now A->>DB: INSERT nuevo refreshToken A-->>F: { accessToken, refreshToken } (nuevos) F->>F: Actualiza localStorage, reintenta request original end rect rgb(245, 243, 255) Note over U,DB: Flujo 4 — Switch de tenant (sub-empresa) U->>F: Selecciona sub-empresa en dropdown F->>F: Guarda sesión actual en parent_session F->>A: POST /auth/switch-tenant { childTenantId } A->>DB: Verifica child.parentTenantId = user.tenantId A->>DB: findOrCreate usuario espejo en sub-empresa A->>DB: INSERT refresh_token (contexto sub-empresa) A-->>F: { accessToken, refreshToken, user } (sub-empresa) F->>F: window.location.replace('/dashboard') end
05

Flujo de inscripción, progreso y certificados

Desde la inscripción del empleado hasta la generación del certificado PDF

Un empleado se inscribe en un curso publicado. Conforme completa lecciones (video, texto, archivo) y pasa los quizzes, el progreso se registra. Al completar el 100%, se genera automáticamente un certificado con PDF descargable y URL de verificación pública única.

Flujo de suscripciones y límites por plan

Planes FREE / BUSINESS / ENTERPRISE y restricciones de recursos

Al registrar una empresa se asigna el plan FREE automáticamente. Los límites se validan en cada operación relevante (crear usuario, crear curso, crear sub-empresa). El upgrade se gestiona mediante Stripe (actualmente en modo mock).

Referencia de entidades

Campos, tipos, claves y relaciones de las tablas principales

Convenciones: PK Clave primaria   FK Clave foránea   UK Unique constraint. Todos los IDs son cuid() de Prisma. Soft-delete vía deletedAt.

EntidadCampo claveDescripciónRelaciones principales
Tenant slug UK Empresa o sub-empresa. Identidad de login. → Users, Courses, Subscription, StorageUsage
User tenantId+email UK Un email puede existir en varios tenants (espejo). → RefreshTokens, Enrollments, Certificates
Course status: DRAFT / PUBLISHED / ARCHIVED Solo cursos PUBLISHED son visibles al empleado. → Modules → Lessons → Quiz
Enrollment userId+courseId UK Un usuario no puede inscribirse dos veces al mismo curso. → LessonProgress → Certificate
Certificate publicUuid UK URL pública de verificación. No requiere auth. → Enrollment, User, Tenant, Course
RefreshToken tokenHash UK Solo el hash SHA-256 se guarda. El token raw nunca se persiste. → User
Plan type: FREE / BUSINESS / ENTERPRISE Límites de recursos por tenant. Seeded en migraciones. → Subscriptions
UserInvite tokenHash — expira en 7 días Invitación pendiente de aceptar. Se convierte en User al registrarse. → Tenant, invitedBy User
